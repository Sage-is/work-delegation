work-delegation

Expensive models should judge. Cheap models should type.

The problem

Your premium AI assistant spends most of its tokens typing file content — docs pages, style passes, docstring sweeps — work a free model handles fine.

The split

work-delegation gives your assistant a wrapper called delegate-edit. The assistant writes a precise brief. A cheaper model does the typing, over a direct API call or the opencode CLI. The assistant reads the git diff before anything counts as done. Judgment stays expensive. Typing gets cheap.

Measured, not promised

On 2026-09-13 a Go plan lane scored 4 of 4 at 8 to 19 seconds per task. The free tier, no key, scored 4 of 4 at 18 to 44 seconds through the opencode CLI. One lane list serves both. Every diff is reviewed. The results ship in the repo.

Guardrails

The delegated model gets five file tools — read, write, edit, ls, and done — and no shell. Only the opencode path serializes through a machine-wide lock and denies git, recursive delete, and the web. A hardlink guard protects linked files. A stalled run fails fast instead of hanging. One environment variable, DELEGATE=0, shuts the whole thing off.

Every harness

One make install covers Claude Code, Codex, opencode, and Pi — the same brief-delegate-review loop, whichever assistant you run.
